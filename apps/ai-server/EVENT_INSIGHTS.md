# イベント起点の気づき

`buildEventInsight` はBackendが検出した期限確認・不足書類・専門家確認イベントを、根拠と版付きのInsight候補へ変換する。LLMの巡回や期限計算は行わない。一般的な案件変更は未対応として返し、架空の発見を作らない。

同一Case/eventはRunが変わっても同じresultIdになる。BackendはCase/eventから一意なInsight IDを作り、結果の受付と保存を同じトランザクションで実行する。別Runの同じイベントでも重複を作らない。

DOCUMENT_REQUEST・ESCALATION_PROPOSALは表示する気づきと別の候補として返す。正式状態の変更には既存のProposal/人の確認が必要。気づきの生成だけで引継ぎ完了・外部連絡を行わない。

この関数へのeventは認証済みBackendから取得し、最新Case/Task版と照合する。モデルや公開API入力をそのまま渡さない。期限・根拠はBackendの確定Rule情報を使い、AIの法的判断を追加しない。

計画Contextの`insightEvents`はBackendが登録済みTask/Deadlineから作る。確定済みRule付きの重要期限、検査済み資料と紐付けられない必要書類、ESCALATEDのTaskが対象。期限を再計算したり、未確認の期限を通知したりしない。大量のイベントは切り捨てずContext取得を拒否する。

P-03の結果報告stepでイベントを気づきに変換し、`case_planning.insights`として認証済み結果APIへ渡す。Case/Task/期限の版・event ID・結果ID・根拠所属を再検証して、既存の公開Insight一覧へ保存する。Caseや根拠の更新後はSTALE、参照不可ならUNAVAILABLE。同一イベントを最新Contextで再検証した場合は同じInsightの鮮度だけを更新し、利用者の既読/非表示を保持する。

これは計画実行時の検出と配送。時間経過だけを起点とする定期実行やイベント専用Runのスケジューラは別途Backendの検査イベントへ接続する。一般的な案件変更からの推測通知は作らない。
