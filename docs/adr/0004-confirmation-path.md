# ADR 0004: Command・Proposal・Approval・本人Decisionの確定経路

- 状態: 中核を実装済み。Entity別の適用は子Issueへ分割
- 日付: 2026-09-20
- 関連Issue: #11（親）、#9（Task）、#10（実行制御）、#13 / #14 / #16（Entity別）

## 背景

業務状態を変える経路が複数あると、どこかで認可・版・監査・冪等性の検証が抜けます。
とくに「承認したのに反映されていない」「承認した内容と違うものが反映された」は、利用者が検知しにくく、影響が大きい失敗です。

## 決定

### 1. 承認は「その人が見た版の内容」に結び付く

提案は版を持ち、版ごとに内容のhashを持ちます。承認はその版とhashを指します。承認の要求には、利用者が見た版とhashを含めさせます。一致しなければ拒否します。

内容を訂正するときは、既存の版のpayloadを書き換えません。新しい版と新しいhashを作り、対象を失った承認は期限切れにします。人は新しい版を改めて承認します。編集できる体験は保ったまま、承認した対象が後から変わらないようにしています。

### 2. 承認の受付と業務状態への反映を分けて返す

公開DTOは承認の状態（PENDING / APPROVED / REJECTED / EXPIRED）と、反映の状態（NOT_APPLIED / APPLIED / FAILED）を別に返します。承認を受け付けただけで「反映済み」と表示させません。

### 3. 承認後に再検証してから適用する

承認の時点で、提案の版とhash、提案の状態、案件の版、根拠の所属と版を改めて検証します。提案を作ったときの案件の版と現在の版が違えば、その提案はSTALEにして適用しません。利用者の更新を、古い前提の提案で上書きしないためです。

STALEの記録は、中断した適用のTransactionとは別に書き込みます。中断したTransactionの中で書いても巻き戻り、同じ提案が承認待ちのまま残ります。

### 4. 反映は承認と同じTransactionで確定する

Entityの変更、承認の記録、提案の状態、監査、Outboxを1つのTransactionで確定します。反映だけが成功して承認の記録が残らない、あるいはその逆を作りません。

### 5. 反映できない種類は理由を添えて拒否する

種類ごとの適用処理は、そのEntityを担当するIssueが登録します。登録されていない種類は適用できず、`FEATURE_NOT_CONNECTED` を返します。成功したふりをしません。

### 6. 本人の意思は下書き・報告・確定を区別する

家族が入力した下書き、本人以外による報告、本人自身による確定を別の状態にします。選択欄が埋まっただけ、他人が報告しただけでは確定にしません。

確定できるのは、Case membershipがその Person と紐付いている利用者だけです。案件の所有者であっても、他の家族の意思を本人として確定することはできません。確定後は、他人の入力で下書きへ戻せません。

### 7. 放棄前ロックは確定だけを根拠に外す

記録が1件も無い状態を「確定済み」としません。登録されている相続人全員が本人として確定している場合にだけ解除します。相続人の範囲そのものはPersonの登録（#13）に依存し、Personが未登録の案件では確定と判定されません。

## 実装済みの範囲

- 提案の提出・訂正・一覧・詳細。根拠の所属と版の検証
- 承認の依頼・承認・却下・期限切れ。版とhashへの結び付け
- 承認後の再検証と原子的な適用。STALE判定とOutboxへの通知
- 本人Decisionの下書き・報告・本人による確定と、放棄前ロックとの接続
- 手続きの提案（TASK_PROPOSAL）の適用処理

## 子Issueへ分割した範囲

1. 財産・債務・契約・関係者の適用処理（#40）は実装済み。全入力値の固定と対象Entityの版検証を行います。
2. AI由来の提案とCase lease / fencingTokenの連携、結果の鮮度検証（#41）。#36 の内部API契約に依存します。
3. 書類要求・専門家引継ぎ・根拠の提案の適用処理（#42）は実装済み。承認必須で、外部連絡はしません。

Entity別の入力と適用範囲は [Proposal payload契約](../api/proposal-payloads.md) を参照してください。

## 対象外

Agentの推論とプロンプト、外部機関への送信・解約・送金、専門的判断の自動確定は含みません。自動適用を許す提案の種類は、レビュー済みのPolicyに限ります。現時点では自動適用を許す種類はありません。
