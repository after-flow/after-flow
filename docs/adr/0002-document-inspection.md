# ADR 0002: 書類検査とマイナンバー検知・マスキングの提供条件

- 状態: 方式は未決定。検査Portと隔離の契約だけを先に確定する
- 日付: 2026-09-20
- 関連Issue: #19（親）、#8（書類API）、#12（同意）、#10（AIへの配信）

## 背景

DocumentUploaderは利用者に「検知・マスキング」を説明します。一方でBackendには検査の実装がありません。
説明と実装が食い違ったまま書類を受け付けると、利用者は安全だと理解して原本を投入します。

検知・マスキングの方式は、精度の検証条件、対象形式、外部サービスへ送るかどうか、原本と加工版の保持方針まで含めて決める必要があります。これらは技術判断だけでは決められません。

## 決定

### 1. 検査を通っていない書類を安全側の状態として扱わない

保存された書類は `PENDING` から始まります。`PASSED` は実際に検査が完了した場合にのみ設定します。検査器が未接続の場合、状態は `PENDING` のままで、`FAILED` でも `PASSED` でもありません。

公開DTOは「未検査」「検査中」「合格」「拒否」「検査失敗」を区別します。未検査を合格として表示させません。

### 2. 未検査・拒否・失敗の書類をAIへ配信しない

配信可否の判定はBackendが行います。`PASSED` 以外の書類は、内容もメタデータも外部AIへ渡しません。マスキングを掲げる場合、未加工の原本を通常の解析入力にしません。

### 3. 隔離保存と「原本を保持しない」を混同しない

検査前の書類は隔離領域に一時保存します。これは保持しないこととは別です。保持期間、削除の条件、削除の追跡範囲は方式決定時に定めます。

### 4. ファイル名や拡張子による擬似検知を検知と呼ばない

検査器は内容を見る必要があります。ファイル名の判定や、常に成功を返すFakeを実装完了としません。Fakeは基盤の試験にのみ使い、試験であることが分かる名前にします。

### 5. 外部サービスへ送る方式なら同意と情報提供Policyを先に通す

外部の検査サービスへ書類を送る方式を選ぶ場合、#12 のPolicyの対象になります。提供先、目的、保持条件が確定するまで、その方式は有効にできません。

## 未決定事項と決定に必要な入力

| 項目 | 決定に必要なもの |
|---|---|
| 検知方式 | 対象とする番号の表記ゆれ、想定する誤検知率と見逃し率の許容値、業務レビュー |
| 実行場所 | 自前処理か外部サービスか。外部なら提供先・目的・保持条件 |
| 対象形式 | PDFのテキスト層と画像層、JPEG/PNGのOCR要否 |
| マスキング | 原本を残すか、加工版のみを残すか。どちらを解析入力にするか |
| 検証条件 | 合成文書での再現手順と、合格とみなす基準 |
| 失敗時の扱い | 誤検知・見逃し・処理失敗それぞれの利用者向け表示と復旧手段 |
