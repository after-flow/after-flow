# ADR 0001: 認証Providerの選定は未確定のまま、検証をAdapterへ隔離する

- 状態: 未確定（実接続は着手条件を満たしてから）
- 日付: 2026-09-20
- 関連Issue: #6

## 背景

仕様書19章の未確定事項に「認証/デプロイ: Google Cloud系を既定案」とあり、採用する認証Provider、issuer、audience、鍵の配布方法は決まっていません。
一方で公開APIは、認証済みユーザーとCase membershipに限定する必要があります。

既存フロントのログインは、任意のメールアドレスとパスワードで成功するMSWのモックです。これは実認証ではありません。

## 決定

1. トークン検証をIdentity Adapterへ隔離します。Applicationはissuer、audience、署名方式を知りません。
2. issuer、audience、許可する署名方式、鍵の取得元、tenantを載せるクレーム名は、すべて設定で受け取ります。
3. 設定が無い場合に「検証を省略して通す」既定値は作りません。認証未設定のまま起動した場合、認証が必要なAPIはすべて401になります。無効化ではなく全拒否です。
4. 対称鍵と `none` は設定で選べません。公開鍵を知る者が署名を作れる構成を防ぎます。
5. 固定鍵モードは試験とローカル開発のためのものです。`NODE_ENV=production` では選べません。
6. トークンが主張するtenantは、membershipの実在で必ず裏取りします。Providerによってはカスタムクレームを利用者側で設定できるためです。

## 実接続の着手条件

次が確定するまで、ログイン導線まで完了したとは扱いません。

- 採用する認証Provider
- そのProviderのissuer、audience、JWKSのURI
- tenantを載せるクレーム名と、その値を誰が書き込めるか
- セッションの更新と失効の契約（フロントの再ログイン導線に影響します）

自前のパスワードDBは追加しません。旧 `/auth/login` の成功固定を実認証として移植しません。

## 影響

- フロントの実接続にはProviderのログイン導線が必要です。対応付けは #3 の対応表で扱います。
- Case membershipの付与方法（招待、初回作成時の自動付与）は #7 以降で扱います。
- サービス間認証（Backend ↔ AI）はこのADRの対象外で、#10 が扱います。
